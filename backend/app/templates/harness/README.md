# {project_name}

LLM evaluation harness generated by AI Eval Studio.

## Overview

This project provides a complete evaluation harness for comparing multiple LLM models against a test dataset. It uses DeepEval for metrics scoring and AWS Bedrock for model inference.

## Setup

1. Install dependencies with uv (recommended) or pip:

```bash
# Using uv (recommended)
uv sync

# Or using pip
pip install -e .
```

2. Configure AWS credentials:

```bash
export AWS_PROFILE=your-profile  # Optional, defaults to default profile
```

The Bedrock region is not read from `AWS_REGION`: `run_eval.py` always passes
`--region` (default `us-east-1`, see AWS Configuration below) into the config.
Models routed through Bedrock Mantle use the region recorded for them in
`src/model_descriptors.json`.

## Usage

### Basic Usage

Evaluate all configured models with baseline prompt:

```bash
python run_eval.py
```

### Specify Models

Evaluate specific models with FULL Bedrock model ids (comma-separated or
space-separated — ids are passed to Bedrock verbatim):

```bash
# Comma-separated
python run_eval.py --models us.amazon.nova-lite-v1:0,openai.gpt-5.6-luna

# Space-separated
python run_eval.py --models us.amazon.nova-lite-v1:0 openai.gpt-5.6-luna
```

If omitted, the `models` list from `src/config.py` is used.

### Specify Prompt Version

Use a specific prompt version:

```bash
python run_eval.py --prompt-version v2
```

This loads the prompt from `prompts/v2.md`.

### Limit Examples (Testing)

Evaluate on a subset of examples:

```bash
python run_eval.py --max-examples 10
```

### Override Judge Model

Use a different model for LLM-as-a-judge metrics. Like `--models`, this takes
a FULL Bedrock model id, passed to Bedrock verbatim:

```bash
python run_eval.py --judge-model us.anthropic.claude-haiku-4-5-20251001-v1:0
```

If omitted, `EvalConfig.judge_model_id` from `src/config.py` is used; if that
is empty too, each target model judges its own outputs.

### AWS Configuration

Specify AWS region and profile:

```bash
python run_eval.py --region us-west-2 --profile my-profile
```

### JSON Progress Mode

For platform integration, emit JSON progress events:

```bash
python run_eval.py --json-progress
```

This outputs JSON lines to stdout for tracking:
- `{"event": "generating", "model": "...", "current": 5, "total": 100}`
- `{"event": "scoring_start", "model": "...", "total": 100}`
- `{"event": "scoring_complete", "model": "...", "passed": 85, "total": 100}`
- `{"event": "complete", "model": "...", "passed": 85, "total": 100}`
- `{"event": "results", "file": "eval_results_baseline_20260408_120000.json"}`

## Customization

### Adding Models

Edit the `models` list in `src/config.py` (full Bedrock model ids,
cheapest-first — the optimizer relies on this ordering):

```python
models: list = field(default_factory=lambda: [
    "us.amazon.nova-lite-v1:0",
    "your.bedrock.model.id",
])
```

Then refresh `src/pricing.json` so cost tracking covers the new model
(inside the platform: ask in chat / `refresh_pricing`; standalone: add an
entry by hand — see Cost Tracking below).

### Changing Metrics

Edit `src/metrics/metrics.py` to modify the metrics. **Prefer DeepEval's shipped
metrics** — reach for a custom one only when none of them fits:

```python
from deepeval.metrics import ExactMatchMetric, AnswerRelevancyMetric

def build_metrics(judge_model: BedrockRuntimeModel) -> list:
    return [
        ExactMatchMetric(),                       # deterministic, no judge cost
        AnswerRelevancyMetric(model=judge_model),  # LLM-as-a-judge
    ]
```

`ExactMatchMetric` compares `expected.strip() == actual.strip()` — whitespace
trim only, no case folding — so it cannot score a wrong answer as correct. It is
strict: a model that wraps its answer in backticks or a fenced block, or appends
a semicolon, scores 0. That failure is visible in the results, which is the safe
direction to fail.

If your task genuinely needs tolerance the shipped metric does not give, you
have to write a normalizer — and an over-lenient normalizer is the one error
nothing downstream can catch, because it scores wrong answers as correct. The
module docstring in `src/metrics/metrics.py` carries three checks to run over
your own dataset before trusting one (no-collision, idempotent, fixed-point on
ground truth). Read it first.

### Modifying Dataset Format

Edit `src/evaluation/dataset_loader.py` to customize:
- `load_test_cases()` — how test cases are loaded
- `format_user_message()` — how prompts are formatted

## Cost Tracking

Generation costs come from `src/pricing.json` — the ONLY pricing source
(written by the platform at harness validation, refreshed on model
changes). Per-case costs land in `additional_metadata.generation_cost`;
run totals in `generation_cost_usd` / `judge_cost_usd`.

A model with no `pricing.json` entry reports its cost as **null** (with a
one-time stderr warning) — never an estimated or invented number. To fix,
add an entry with per-1M-token USD rates under the top-level `models` key,
which is the only part of the file the runner reads (the `_`-prefixed keys
the platform writes alongside it are informational):

```json
{
  "models": {
    "your.bedrock.model.id": {"input": 0.30, "output": 2.50}
  }
}
```

An entry needs both `input` and `output`; without them the cost stays null.
Optional `cache_read` / `cache_write` rates are used when present; absent,
cache tokens bill at the model's input rate (a slight over-estimate).
